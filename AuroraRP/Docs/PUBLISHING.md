# Публикация AuroraRP: один плагин (всё внутри) + необязательный палет

Эта инструкция — про то, как раздать мод игрокам так, чтобы им почти ничего не пришлось делать.

## Коротко

| Что | Куда выкладывать | Как у игрока это появляется |
|---|---|---|
| **`AuroraRP.dll`** — код + вся красота (меню, иконки, анимации, партиклы, звуки) + дефолтный конфиг | **Thunderstore** (+ GitHub Releases для автообновления) | один клик в Gale/r2modman; вручную — просто положить в `Mods`. Отдельных скачиваний не требует |
| **Плагин `AuroraRPUpdater.dll`** | тот же пакет / GitHub Releases | один раз; дальше обновляет DLL и зависимости (BoneLib, LabFusion) сам |
| **Палет** (терминал, принтер, двери) — **необязательно** | **mod.io**, страница BONELAB | сам, скачивается Fusion во время игры. Нужен только чтобы контент видели игроки **без мода** |

## Сборка через GitHub Actions (автоматически)

В репозитории лежит `.github/workflows/build.yml`. Он запускается:
- при пуше тега `aurorarp-v*` (то есть на каждый релиз);
- вручную: **Actions → Build AuroraRP → Run workflow**.

Что CI собирает **сам** (без Unity и без игровых файлов):
| Артефакт | Откуда |
|---|---|
| `AuroraRPUpdater.dll` | `AuroraRP/Updater` — качает MelonLoader 0.6.6 с его релиза и компилирует плагин |
| `AuroraRP-Thunderstore-1.0.0.zip` | пакет для Thunderstore с плагином внутри |
| `AuroraRP-pallet-src-1.0.0.zip` | исходный контент палета (конфиг, документы) |

Всё это автоматически прикладывается к релизу, откуда его забирает `AuroraRPUpdater`.

**Чтобы CI собирал ещё и `AuroraRP.dll`** (сам мод), дайте ему игровые сборки одним из способов:
- секрет `BONELAB_ASSEMBLIES_URL` — прямая ссылка на zip с папкой
  `BONELAB_Data/il2cpp/MelonLoader/Il2CppAssemblies`;
- либо секреты `BONELAB_ASSEMBLIES_REPO` (`владелец/приватный-репозиторий`) и
  `BONELAB_ASSEMBLIES_PAT` (токен с доступом к нему) — тогда CI сам скачает zip из релиза
  этого приватного репозитория.

BoneLib и LabFusion CI тянет сам из их публичных релизов. Игровые сборки в публичный доступ
выкладывать нельзя — держите их в приватном месте, доступном только раннеру.

**Что CI собрать не может:** `AuroraRP.dll` вместе с зашитой красотой и сам палет — для этого
нужны Unity и игровые сборки. В Unity: `AuroraRP → 3. СОБРАТЬ ВСЁ` (он сам соберёт контент,
зашьёт пак в DLL и положит файлы в `Builds/`). К релизу приложите `AuroraRP.dll` руками;
палет-архив — по желанию (нужен только для игроков без мода).

## Как выпускать обновления (после настройки — 3 минуты)

1. Поднимите версию в `Mod~/AuroraRP.csproj` (`AssemblyVersion`/`Version`), в
   `Editor/AuroraRpPaths.cs` (`ModVersion`), в `Thunderstore/manifest.json` и в `update.json`.
2. Unity → **AuroraRP → 3. СОБРАТЬ ВСЁ** — получите `AuroraRP.dll`, `AuroraRPUpdater.dll`,
   `Builds\AuroraRP_v<версия>.zip` (для игроков) и `Builds\AuroraRP-pallet-<версия>.zip`
   (для mod.io и автообновления).
3. GitHub → Releases → тег `aurorarp-v<версия>`: CI сам соберёт плагин, Thunderstore-пакет и
   архив исходников. Приложите руками **`AuroraRP.dll`** (в нём уже вся красота) и, если
   выкладываете, `AuroraRP-pallet-<версия>.zip`.
4. Обновите `AuroraRP/update.json` в репозитории: `version`, `dll`, `dllSha256`.
   Поля `pallet`/`palletVersion` — **только если палет выложен**; иначе оставьте пустыми.
   Там же список `dependencies` — моды, которые плагин доставит игроку сам (BoneLib, LabFusion).
5. Палет на mod.io — по желанию (нужен только игрокам без мода).

Дальше всё само: у игроков плагин подтянет свежий `AuroraRP.dll` и палет до запуска игры.
`dllSha256` в `update.json` заполнять не обязательно, но полезно (защита от битой закачки):
`certutil -hashfile AuroraRP.dll SHA256` в Windows.

### Красота внутри DLL

Всё визуальное (иконки, скин меню, партиклы, купюра для перевода, звуки, анимации) лежит в
палете-контенте и ищется по именам — см. таблицу в `README.md`. Правки: открыть префаб
`Assets/AuroraRP/Pallet/Prefabs/AuroraVisualSet.prefab`, подменить/добавить объекты и нажать
**AuroraRP → 3. СОБРАТЬ ВСЁ**. Сборка сама упакует бандлы в `Mod~/Runtime/Assets/aurorarp.pack`
и вшит их в `AuroraRP.dll` — отдельно раздавать ничего не нужно. Хотите только пересобрать пак
без полной сборки — кнопка **AuroraRP → 7. Вшить красоту в DLL (собрать пак)**.

Пак — это zip: `manifest.json` (версия, карта `barcode → префаб`, шейдер/текстура/цвет
материалов), дефолтный `config.json` и все `*.bundle`. При запуске мод читает его из памяти
через `AssetBundle.LoadFromMemory`. Материалы с вырезанными шейдерами «ремонтируются» в
рантайме по данным `manifest.json`.

Если пака в DLL нет (сборка без Unity-контента), мод работает как раньше: сначала пробует
палет (`usePalletVisuals`), затем кодовые заглушки (нарисованные иконки, синтез звука).

### Игроки без мода

Палет у них скачается сам, а «физические» действия (оплата за руку, покупка двери удержанием)
выполняет хост: код читает то, что и так синхронизирует Fusion (руки, голову, захваты).
Ключи `peerBridge*` и `passive*` в палетном конфиге включают и настраивают это поведение.
Меню, роли и магазин игроку без мода показать нельзя — интерфейс рисует только код.

### Где живут настройки системы

`Assets/AuroraRP/Pallet/config.json` — **настройки системы**: роли, цены, лимиты, стартовые
наборы, каталог оружия, тексты. Порядок применения (каждый следующий перекрывает предыдущий):

1. **дефолт из DLL** — копия этого файла внутри `AuroraRP.dll` (пак), поэтому у игрока с
   плагином сразу правильные настройки, даже без палета;
2. **палетный** `config.json` — если палет установлен (у всех серверов сразу единые настройки);
3. **личный** `MelonLoader\UserData\AuroraRP\config.json` — перекрывает всё, не теряется
   при обновлениях (плагин сам переносит настройки в UserData перед перезаписью).

> Плагин обновляет код **только** для тех, у кого он поставлен. Раздавайте `AuroraRPUpdater.dll`
> в том же архиве/пакете, что и мод, — тогда автообновление есть у всех.

> **Почему DLL нельзя «заставить скачаться» автоматически.** Для code-мода нужен MelonLoader,
> а он читает файлы только из папки игры `BONELAB\Mods`. Ни mod.io, ни LabFusion не могут
> положить туда файл и загрузить код — таких прав у них нет. Это ограничение самой игры:
> контент — автоматически, код — руками (или менеджером модов). Поэтому мы и убрали вторую
> загрузку: всё, что можно, теперь лежит в одной DLL, а палет остался необязательным.
>
> **Почему безмод-игрок не увидит красоту из DLL.** Кастомные модели/текстуры нельзя передать
> по сети — Fusion синхронизирует только позиции и состояния. Значит, всё видимое должно быть
> на диске у клиента: либо в его DLL (если у него мод), либо в палете, который Fusion скачает.

## Шаг 1. Собрать

Unity → **AuroraRP → 3. СОБРАТЬ ВСЁ** (создаёт контент, вшивает пак в DLL, собирает DLL,
апдейтер, архивы и ставит всё в игру).

Появятся:

- DLL — `AuroraRP/Mod~/bin/AuroraRP.dll`;
- палет — папка в `...\LocalLow\Stress Level Zero\BONELAB\MODS\AuroraRP` и архив
  `AuroraRP/Builds/AuroraRP_v1.0.0.zip`.

## Шаг 2. Палет → mod.io

1. Зайдите в кабинет mod.io (страница игры **BONELAB**).
2. **Add mod** → тип: **Spawnable** (или Level/Avatar — что у вас в палете).
3. Загрузите zip палета, заполните название/описание (русский + английский), поставьте теги
   `Patch 6`, `PC`.
4. Опубликуйте. В кабинете разработчика посмотрите **Mod ID** — это число (например, `1234567`).
5. Впишите его в конфиг мода: `UserData/AuroraRP/config.json` → `"modioModId": 1234567`.

С этого момента:

- у **хозяина** лобби палет ставится через игру (`Mods` → AuroraRP → Subscribe) — это
  гарантирует, что Fusion знает mod.io-ID палета и сможет отдавать его клиентам;
- у **игроков** палет скачивается сам, когда хост спавнит предмет мода (или заранее — мод
  сам потянет его по `modioModId`, если у игрока палета нет).

## Шаг 3. DLL → Thunderstore

1. Правьте версию в `AuroraRP/Thunderstore/manifest.json`, если выпускаете обновление.
2. Запустите `AuroraRP/Thunderstore/pack_thunderstore.cmd` — получите
   `AuroraRP/Builds/AuroraRP-Thunderstore-1.0.0.zip`.
3. Залейте архив на https://thunderstore.io/c/bonelab/ (сначала создайте команду/namespace).
4. Готово: игроки ставят мод в один клик (Gale / r2modman / ThunderstoreModAssistant в игре).

Хотите, чтобы менеджер модов ещё и BoneLib ставил автоматически — добавьте в
`dependencies` строку вида `"gnonme-BoneLib-3.1.3"` (номер версии — актуальный).

## Шаг 4. Инструкция для игроков (можно копировать в Discord)

> **AuroraRP — как подключиться**
>
> 1. Установите MelonLoader и BoneLib.
> 2. Поставьте AuroraRP: через Gale/r2modman (BONELAB → AuroraRP → Download with dependencies)
>    или вручную — файл `AuroraRP.dll` в папку `BONELAB\Mods`.
> 3. Запустите игру, зайдите в mod.io (Void G114 → Mods) — это нужно, чтобы работали
>    авто-скачивания.
> 4. Подключайтесь к лобби хоста. Палет мода (терминал, принтер денег) скачается сам —
>    играть можно сразу.
> 5. Меню мода — **Y на левом контроллере + A на правом**.

## Частые проблемы при публикации

| Симптом | Причина и решение |
|---|---|
| Палет не скачивается у игроков | Игрок не вошёл в mod.io в игре, или в Fusion выключено «Download Spawnables», или у палета нет mod.io-ID (мод ставился вручную, а не через mod.io). |
| Fusion скачал палет, но предметов нет | Палет в mod.io собран не для PC (Windows-платформа) или не тот тип. |
| У игрока нет ролей/денег | У него нет `AuroraRP.dll` — код-мод, ставится вручную. Хост видит таких игроков в меню («Без AuroraRP»). |
| Ошибка версии DLL у игроков | Разные версии мода у хоста и игрока: обновите мод у всех (Thunderstore покажет апдейт). |
